## Implemented

- Rust contract compiler/evaluator with PASS, FAIL, and UNKNOWN outcomes.
- Native and WASM parity workflow over 144 synthetic scenarios.
- Local Playwright collector with sandbox enabled, root-launch refusal, external-target rejection, context-wide origin filtering, redacted observations, and seeded browser fixtures.
- Local evidence packer and SQLite scenario index.
- API-only Worker for caller-supplied JSON with D1-backed revocable tenant keys, per-tenant SQLite Durable Object request/day/concurrency quotas, bounded request parsing, no CORS, and no application-level request/report persistence.
- Security-header protected static research-preview assets served from the staging Worker configuration.
- Aggregate-only real-defect scoring and consented-pilot preparation tools; no external data was used.
- A disabled-by-default DNS TXT domain-challenge component adds tenant-bound, hashed, expiring, single-use proof records and exact-origin revocation. A pinned `tldts` PSL adapter includes private suffixes and is wired into the Worker. The code is included in the feature-disabled staging bundle; mocked resolver route tests and SQLite migration smokes cover local behavior, but no live DNS proof or D1 route transaction has been verified.
- A tenant-scoped scan intake/status API and encrypted D1 dispatch outbox now exist locally behind explicit false-by-default gates. The API enforces exact verified HTTPS origin, bounded passive capture specs, evaluator contract compilation, per-tenant idempotency, and server-side quotas; it stores only AES-GCM ciphertext for at most 24 hours and queues identifiers only. Migrations `0008` and focused tests cover local SQLite/Node behavior. Staging still has no queue binding/consumer, Cron Trigger, browser runner, approved network egress, or applied migration `0008`; hosted URL scanning remains disabled and is not a commercial service.
- Added scan-policy/job/artifact metadata with per-minute, daily, and concurrency guards, idempotency, origin freshness/revocation checks, redaction and retention constraints. Migrations `0001`–`0003` are applied to staging; read-only aggregate checks found zero tenant/challenge/origin/scan-policy/job/artifact rows. An R2-first deletion core and exact-flag-gated scheduler helper have fake-binding tests; the Worker scheduled handler is bundle-checked but not invoked in Workerd. No R2 binding, Cron Trigger, Queue binding/consumer, or active retention service is configured. The scan intake/outbox implementation is local and feature-disabled.
- Added local domain-metadata and scan-job retention paths with audited deletes, bounded batches, operator-supplied windows, preserved quota history, and cleanup for jobs without artifacts. Added opt-in scan recovery, a scan execution-authorization core, and an internal tenant-suspension helper that cancels queued/running jobs before suspension; migration `0007` cancels jobs on origin revocation and guards direct suspension. A tenant-scoped scan intake/status route and encrypted outbox with key-ID rotation are implemented but disabled; they do not execute scans. Migrations `0004`–`0008` and these helpers are verified with local SQLite/fake bindings only, are not applied to staging, and no queue consumer or runner uses the authorization core. Cloudflare D1 and runtime execution remain unverified. Route and key rotation operations are documented in `SCAN_INTAKE_OPERATIONS.md`.
- Pinned all remote actions in the CI and fuzz workflows to upstream full commit SHAs, disabled checkout credential persistence, and added weekly Dependabot action updates. CI checks the pin policy and the curated source manifest/checksum inventory; neither check represents a hosted CI pass.
- Added explicit timeouts to every CI job, a 60-minute maximum policy check, and same-ref cancellation for superseded main-workflow runs. These controls bound duplicate CI work, not production service cost or capacity.
- Added a local refresh/check command for the curated source inventory, including current CI policy and release-gate documentation. Refresh refuses to mark Rust or browser verification as complete.
- Versioned the real-defect evaluation input as a strict JSON Schema; aggregate reports now group by source layer and predicate, document overlapping multi-layer groups, and require multi-review consensus/adjudication for every row before the evidence gate can pass. The JSONL reader rejects duplicate object keys and the CLI prevents output from overwriting its source dataset.
- Hardened local evidence packaging: raw-input inclusion requires explicit synthetic-only mode, each raw JSON input is parsed and capped at 256 KiB before output creation, and verification rejects symlinks, unlisted files, malformed artifact metadata, oversized artifacts, and report/manifest identity mismatch. Hashes remain change-detection fingerprints, not signatures or authenticity proof.
