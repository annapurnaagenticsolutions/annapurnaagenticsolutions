## Compiled-WASM integration and local sizing

The persistent test suite under `tests-wasm/` instantiates the actual generated `worker/pkg/invariantc_bg.wasm`, connects its generated bindings to `worker/src/handler.mjs`, and exercises representative PASS, FAIL, and UNKNOWN fixtures plus the authentication gate. Run it after `npm run build:wasm` with `npm run test:wasm-worker`. It is separate from `npm run test:js` so a clean checkout does not require generated WASM artifacts for the ordinary JS unit suite.

`npm run measure:wasm-worker` warms each of the 144 synthetic cases five times, then runs 50 measured rounds per case (7,200 requests) through the compiled-WASM handler in Node 24.15.0 on a 13th Gen Intel Core i7-13650HX. The current observed p50/p95/max handler latencies were 0.0664/0.1304/0.5905 ms; measured process CPU was 579 ms total (0.08042 ms/request). Request bodies ranged from 355 to 563 bytes (median 425). The WASM module was 254,851 bytes and its linear memory was 1,179,648 bytes. Sampled peak process RSS was 75,292,672 bytes; after optional GC it was 74,870,784 bytes, about 17.9 MB above the pre-warm-up process RSS (after module and fixture initialization). The JSON measurement is written to ignored `target/local-resource-measurement.json`.

The release bundle was measured with the documented local-only command:

```powershell
npm run worker:dry-run
```

Earlier Wrangler 4.148.0 dry-runs reported 270.91 KiB total / 107.87 KiB gzip before domain verification, 289.58 KiB / 111.98 KiB with domain verification, 294.61 KiB / 113.13 KiB with inert retention, and 484.21 KiB / 165.96 KiB before scan intake/outbox. The current local bundle is 522.33 KiB total / 174.05 KiB gzip and includes the disabled intake/status route, encrypted outbox with key-ID rotation, bounded request-complexity checks, and bounded dispatch/recovery/retention handlers. Local migrations `0004`–`0008` are not applied to staging. The intake is not a browser runner; no Queue/R2/Cron binding or encryption key is configured. The last recorded staging release is version `92c6912c-b071-443f-ad27-0fb3df1dd1a7`; no updated version was deployed. The prior live smoke covered health, assets/CSP, and unauthenticated rejection only. Bundle artifacts and resource figures are machine/toolchain-specific. Node measurements do not establish network transport, Cloudflare Workerd CPU, isolate memory, D1 behavior, or production behavior.

`npm run worker:migrate-local` applied migrations `0002` and `0003` to Wrangler's local D1 emulator. The current local Worker started, but its HTTP smoke could not connect because the environment returned `connect EACCES 127.0.0.1:8787`; the temporary synthetic tenant/key and token file were removed. A previously completed `worker:smoke-local` and `worker:load-local` run passed against loopback Workerd using synthetic rows/keys, including 4,096 evaluations at concurrency 16 over 37.456 seconds with no failures. Those historical local checks do not verify the current migrated runtime, remote Workerd resources, or production capacity.
