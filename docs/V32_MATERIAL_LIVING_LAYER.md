# v3.2 — Material Living Layer

## Objective
Test whether Annapurna can feel less like DOM elements moving on a page and more like one responsive material environment, without introducing a new WebGL stack or another visible control surface.

## Material cycle
Every material response follows one bounded sequence:

**signal → travel → formation → settling**

A response must be caused by a real interaction state. It does not run as a decorative background loop.

## Home material bridge
A lightweight fixed Canvas2D layer is lazy-loaded only when needed. On deliberate world selection, particles leave the selected world, cross from the ecosystem into the copy region, briefly organize around the most relevant visible semantic text, and then settle back toward the Annapurna core.

World-specific formation grammar:
- AI Solutions → governed lanes;
- WonderHub → constellation;
- Idea Hub → practical block field;
- AXON → typed lanes;
- Website Studio → nested experience frames;
- Software Lab → experimental grid.

If the main hero impact word is outside the viewport, the material response targets the visible world name or journey focus instead.

## Semantic typography
No impact word is underlined. Material emphasis uses only depth, focus, shadow and temporary particle occlusion. The word itself remains normal readable HTML.

## Explore
Deliberate world selection temporarily changes the Atlas material field and selected-node halo. No new panel or metric surface was added.

## Interactive Lab
Changing the active model briefly alters the theatre field so the environment acknowledges the change before settling. The underlying simulations and truth boundaries are unchanged.

## Performance architecture
The material renderer is `assets/material.js`, loaded with dynamic `import()` only when Home needs the effect. The core `site.js` remains inside the pre-existing 24 KB gzip ceiling. The material module has its own 3 KB gzip budget.

## Reduced motion / mobile
The bridge canvas is not used under `prefers-reduced-motion` or narrow mobile layouts. Content, navigation and state changes remain available without the effect.
