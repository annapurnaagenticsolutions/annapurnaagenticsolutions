# Vidya Yantra — Implementation Memory

## Decisions

- The prototype is a **browser-first Babylon.js game**, not a native build. It does not depend on audio so browser autoplay limits are irrelevant.
- The world is intentionally original and learning-driven, informed by broad knowledge traditions rather than any direct retelling of common epics or sacred scripture.
- Generated art is hosted under `/manus-storage/` and is never committed into the WebDev project tree.
- Camera style: fixed three-quarter orbit with a damped target. No pointer-lock, physics plugin, pathfinding, custom shaders, procedural terrain, or imported GLB models.
- `?demo` must play a deterministic visual sequence for verification while normal keyboard controls remain live.
- Browser verification confirmed the live page renders the full game world, HUD, player, yantra rings, glyphs, landmark figures, and demonstration quest state. The first automated capture occurred during dependency optimization and was not a valid visual read; subsequent browser inspection showed the actual rendered experience.

The playable scene therefore keeps those image assets documented but uses a more legible procedural citadel skyline, instrument geometry, and material palette; the generated compass mark and Rishi portrait remain visible brand assets in the game HUD.
