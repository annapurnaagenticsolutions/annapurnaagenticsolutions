What is Agentic Systems Lab?

A visual operations console and policy enforcement toolkit for AI agent governance. The Agentic Lab makes agent execution observable through cryptographically sealed evidence chains, pre-execution policy gates, and real-time run visualization.

🔐 Evidence Sealing

SHA-256 hash-chain append-only ledger with cryptographic tamper detection

🚦 Policy Gates

Pre-execution blocking, approval requirements, and audit trails

📊 Live Monitoring

Server-Sent Events stream for real-time agent execution visibility

🔑 Approval Workflow

Short-lived, cryptographically signed approval tokens for sensitive operations

Architecture

Full-stack preview consisting of:

  • Visual Console — React + Vite frontend for replaying agent runs, reviewing evidence chains, exploring live feeds
  • MCP Server Suite — Five Model Context Protocol servers for tool catalog, policy enforcement, evidence ingestion, approval issuance, verification
  • SDKs — Node.js and Python emitters for instrumenting existing agents without framework coupling
  • Evidence Chain — Append-only ledger with SHA-256 hash chain for tamper-proof audit trails

Available Workflows

1. Evidence Verification

npm run evidence:verify -- bundle.json

Cryptographically verify that an evidence bundle's hash chain is intact. Reports sealed/unsealed/tampered status.

2. Policy Proxy

npm run mcp:policy-proxy -- <mcp-cmd>

Pre-execution gate that intercepts tool calls, applies policy (allow/deny/approval), and strips metadata before forwarding.

3. Ingest Server

npm run ingest:dev

HTTP API for agent evidence ingestion, live SSE feed, evidence export, and verification endpoints.

4. Approval Authority

npm run approvals:dev

Issues short-lived, cryptographically signed approval tokens for tools requiring human-in-the-loop control.

5. Stdio MCP Server

npm run mcp:stdio

Dependency-free Model Context Protocol server exposing trace normalization and run summarization.

Deployment Considerations

This is a preview. The ingest server uses:

  • Append-only JSONL ledger (not a production database)
  • Loopback-bound by default (127.0.0.1)
  • In-memory idempotency cache (lost on restart)
  • No persistent key rotation or remote JWKS refresh

For Production:

  • Replace ledger with durable storage (PostgreSQL, DynamoDB)
  • Use identity-aware gateway (OAuth 2.0, OIDC) instead of HMAC-only auth
  • Store approval keys in secrets manager (Vault, AWS Secrets Manager)
  • Deploy behind HTTPS reverse proxy
  • Configure CORS allow-list for browser clients
  • Enable read-side audit (AGENTIC_READ_AUDIT=enabled)
